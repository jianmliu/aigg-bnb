# Gateway M3 implementation

Scope: execute docs/GATEWAY.md M3. Keep current contracts and existing host wake compatible.

1. Relayer: accept epoch-bound, domain-bound signatures from explicitly listed task clients at POST /wake. Invalid/forged/stale requests cannot extend wakeUntil, including while warm. Add current epoch, beacon, distinct eligible providers and votes to /meps.
2. Gateway: validate requests before waking. On a cold epoch sign /wake, poll beacon and eligible providers within GATEWAY_WAKE_TIMEOUT_MS (default 300000), with SSE keepalive during the wait. Once ready, derive a fresh task deadline and follow existing persisted task flow. Timeout spends no task fee, returns 503 + retry advice (response.failed inside an already-open stream). Disconnect cancels pre-post waiting. Coalesce wake calls per epoch, renew only while demand exists.
3. Host dashboard: show models resident in this tab separately from chain eligibility; show settled requests and exact executor BNB earned from TaskSettled and royalty-adjusted task fees. /hosts?instance returns an explicitly bounded recent 5000-block window, shared cached chain scan; unavailable data is not zero. Refresh only while Host view is visible, discard results after wallet/deployment changes.
4. Tests first: extend local anvil integration for signed wake authorization, cold wait, timeout without spend, provider uniqueness and host accounting; browser test for dashboard values and state. Run existing gateway, lazy beacon, frontend and sponsor regression checks, build frontend.
5. Update GATEWAY.md and README with M3 semantics, API/config and accounting window.

No production deployment or live-chain transactions are part of this task.
