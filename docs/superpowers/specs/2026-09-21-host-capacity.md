# Available-capacity admission for stake-weighted task assignment

Approved direction: a host participates in new draws only while it has free concurrent task slots. Capacity does not multiply stake or give duplicate entries in a draw. Under sustained demand a larger host can accept more assignments; idle equally staked hosts have equal individual draw probability.

Use an optional shared on-chain HostCapacity registry for new TaskMarket/MultiAssetTaskMarket deployments. Only authorized markets may reserve/release slots. Hosts explicitly advertise 0..64 slots, default 0 (paused); this is a service commitment, not verified RAM. Slots are global across bases, native/token tasks and markets sharing the registry. Existing unconfigured markets retain their legacy semantics.

Reservations are keyed by market, task ID and host, atomically made during the draw. Busy hosts are skipped and successful draws preserve stake weights. In capacity mode require all requested distinct executors; failed posts roll back reservations and payments. Expiring execution leases use the market's actual task timeout, not caller-controlled task deadline. Release a host on accepted result submission; timed-out leases cease counting even without settlement. Capacity reductions never erase obligations. Completion frees execution capacity but does not remove execution/dispute data retention duties or chosen executor snapshots. No new nonresponse slashing is introduced.

Wire opt-in deployment, read-only cached relayer capacity endpoint and explicit host dashboard controls for committed slots, occupied/free slots and pause. Never infer slots from navigator memory or multiply draw weight by declared slots. UI must remain functional on old deployments. Chain checks remain authoritative under concurrent requests; relayer snapshots are advisory.

Scope: implement the just-approved capacity allocation mechanism. Automatic future-child loading and sampled claim versioning remain the separate previously proposed runtime/protocol work; do not claim them activated by this scheduler. Current browser executes serially, so its dashboard must cap its advertised execution capacity at 1; multi-worker/server operators may commit more through the contract. No live nonupgradeable contract migration or automatic production activation.

Validation: equal-stake equal draw when idle; small host filled while large host continues; global cross-model/cross-market and cross-currency bounds; unauthorized reservation rejection; duplicate release; timeout boundary/recovery; pause/downsize outstanding tasks; full redundancy and payment rollback; legacy mode; UI chain/account changes and capability absence. Run existing Solidity and relevant JS/frontend suites and a new Anvil integration where possible.

Review clarifications: registry wiring is one-shot before the first successful task. HOST_CAPACITY_REGISTRY reuses existing shared capacity (registry owner authorizes new market), while HOST_CAPACITY=true creates a fresh registry. Execution leases remain active at the exact timeout block and expire on the next block. Late submission/release of an expired task cannot free a reused slot. Active leases can exceed a downsized limit; free saturates at zero. The existing bounded 64*redundancy rejection draw may fail in a mostly busy roster despite some free capacity; API/UI do not guarantee successful assignment. Lease occupancy is not a measurement of running CPU work.
